# Хранилище: второй диск, почта без вложений, бэкапы в S3

12.09.2026. Дмитрий: «на старом сервере постоянно кончалось место; на новом
есть второй диск на 100 ГБ — подумай, как хранить фото, архивы, документы,
бэкапы, письма, чтобы разгрузить диск, а фото грузились быстро». Решения по
ходу: копии бэкапов и логов — в S3 Timeweb, старое чистить; вложения писем
на диске не хранить — письмо лежит в облаке почты, за которое платим, файлы
из письма нужны у нас только когда по письму создано предложение или письмо
привязано к предложению.

## Что было

- Второй диск `sdb` вообще не размечен. Всё пользовательское — в одном
  docker-томе на корне; бэкап — ночной tar.gz всего тома рядом с данными,
  копии вне сервера нет.
- Письмо хранилось трижды: `.eml` целиком, каждое вложение файлом (и
  картинки подписей тоже), а фото после промоушена — ещё раз в медиатеке.
  Письма больше 25 МБ не качались вовсе, а страховые шлют по 37 МБ.
- `/media/*` был открыт целиком: ПТС и договоры из `papers` — по прямой
  ссылке без входа.
- Из уборки по расписанию — только `queue:prune-batches`.

## Как стало

**Диск.** `server-setup.sh disk` размечает `sdb` в ext4, монтирует
`/srv/xcar/data` по UUID, ставит `builder.gc` 3 ГБ в `daemon.json`. Compose
— bind-mount'ы вместо томов: `postgres/`, `storage/`, поверх него `media/`,
`private/`, `cache/`. Перенос с томов — `docker compose stop`, `cp -a` из
`/var/lib/docker/volumes/*/_data`, `media` и `private` наверх (внутри
`storage` они стали точками монтирования). Старые тома `xcar_storage`,
`xcar_postgres_data` оставлены на день и удаляются руками.

**Бэкап.** `backup.sh`: дамп базы локально (7 дней), снимки базы и файлов в
restic на S3 (`--exclude '**/conversions'`), ротация 14/8/6, по воскресеньям
prune и check; журналы контейнеров за день — `logs/ГГГГ/ММ/ДД` в том же
бакете, старше 90 дней стираются rclone. Отметка `backups/last-ok` — по ней
`check.sh` ругается, если снимку больше суток. `restore.sh db latest` и
`restore.sh files` прогнаны на проде по-настоящему. Ключи — только в
`/srv/xcar/env/.env` и `CONNECT.local.md`.

Две ямы: `declare` вместо `export` — ключи не доходили до `docker run -e`;
у образа rclone entrypoint — сам rclone, `sh -c` только через `--entrypoint`.

**Почта.** `Sync` берёт `UID FETCH (BODYSTRUCTURE FLAGS INTERNALDATE
RFC822.SIZE)` сырыми строками — штатный лексер webklex режет `"utf-8")`
пополам, поэтому свой `Structure::tokenize`. `Receiver` качает
`BODY.PEEK[HEADER]` и текстовые части по секциям, `Parser::headers()`
разбирает блок заголовков через webklex (адреса, дата, encoded-word),
`Ingest` пишет письмо, адреса и опись вложений (`section`, `encoding`,
имя из RFC 2231), ветку, событие. Потолка на размер письма больше нет:
текст письма на 37 МБ — те же 50 КБ. `ParseMessage` — пересборка с
сервера по UID.

Файл вложения — `Parts::file()`: outbox (диск `cache`) → blob → ящик через
кэш `cache/mail/{id}` на сутки, к одному ящику по очереди (`Cache::lock`).
Привязка ветки к предложению или машине стоянки, промоушен кандидата, новое
письмо в привязанной ветке → `PinThread`: одним соединением на аккаунт
вложения уходят в `private/blobs/ab/<sha256>`; одно фото из пяти писем и
пересылок — один файл. `Attachment::deleted` отпускает blob. В ленте ветки
миниатюра — только у закреплённого файла, у остального значок: тридцать
картинок из ящика по одной на запрос — это тридцать соединений.

Исходящие: файлы черновика в `cache/outbox`, пересылка — тот же blob, что у
исходного; когда копия доехала до «Отправленных», `Sync` перестраивает
опись по секциям и локальные файлы уходят.

Локальный `scripts/imapserver.py` научен частям MIME (`Part` поверх
`email.message`); Twisted ищет заголовки в нижнем регистре, режет параметры
по `;` и оставляет кавычки в значениях — всё это подчищено в `getHeaders`.

**Документы.** `papers` — на диске `private`, отдача `GET /fayly/{media}`
(`Site\FileController`): сотрудник, покупатель по сделке, адресат просьбы,
стоянка по доступу. `media:move-private` переносит уже залитые. Аватар —
`PhotoIngest` 512 px, фото в чатах — 1600 px webp.

**Фото.** Конверсии w320/w640/w960/thumb, оригинал 1600 px — сам верхний
кандидат в `srcset` и полноэкранный просмотр. Холодный слой: `storage:gc`
стирает конверсии у машин, закрытых больше полугода назад (`CoolPhotos`),
`MediaUrl` отдаёт оригинал, открытая карточка досчитывает их в очереди
(`WarmPhotos`). Оригиналы не удаляются никогда.

**Уборка.** `storage:gc` в 04:30: упавшие задачи 7 дней, просроченный
`cache`/`cache_locks`, PDF шеринга 30 дней, части писем сутки, outbox 7
дней, tmp сутки, blobs отвязанных веток 30 дней, blobs без ссылок, файлы
`w1440`, холодные конверсии; `--dry-run` считает. `storage:report` — медиа
по владельцам, private по каталогам, cache, база по таблицам; его печатает
`check.sh` без `--telegram`.

## Проверено

Локально: письмо с четырьмя вложениями — опись есть, `private/mail` пуст;
вложение открывается из ящика в кэш; ветка привязана → четыре blob, `foto1`
из двух писем — один; промоушен → фото в черновике из blob; исходящее с
файлом и пересылкой → отправлено → после синка «Отправленных» опись по
секциям, outbox пуст; `/fayly` сотруднику и покупателю 200, старый адрес не
отдаёт; холодный слой: gc → `[]` и оригинал в URL → warm → конверсии
вернулись.

Прод: перенос на диск данных без потерь, `restic snapshots` два снимка,
`restore.sh` оба пути, `check.sh` — «всё в порядке».
