# Закупка → предложения по контрпредложению (28.09.2026)

## Процесс

Carcade присылает закупку → публикуем → менеджеры называют цены → мы ставим свою цену (`price_final`) →
выгружаем файл Carcade → Carcade возвращает файл с итоговыми ценами по части строк. Эти строки становятся
предложениями.

## Решения владельца (не переспрашивать)

- Берём только лист с колонкой «Итоговая цена контрпредложения». Лист «исключения» (их цена = наша +20%, часть
  уже продана или выкупается) не трогаем — у него такой колонки нет, читатель пропускает его сам.
- Закупочная = их итоговая цена как есть, даже если ниже нашей. Заявленная пустая (равна закупочной).
  Цену продажи ставим руками.
- Цены менеджеров в закупке и наша `price_final` для предложений не значат ничего: они были нужны только для
  файла Carcade. Не показываем, не переносим. Строки, ставшие предложениями, из закупки исключаются.
- После загрузки — черновики; дальше «Оценить»: цена продажи → «В продажу», и сразу следующий.
- Менеджерам, называвшим цену за ТС в закупке, — уведомление при публикации. Видят предложение все менеджеры.
- Вендор «Каркаде» заводится миграцией и привязывается к закупке; «Поставщик» в закупке — выбор вендора.
- Срок приёма подтверждений — обычный (3 дня от публикации).

## Как устроено

- `purchases.vendor_id`, `purchase_cars.offer_id`, `purchase_cars.announced_at` (миграция `2026_10_23_100000_purchase_counter`).
- `Purchases\CounterReader` — OpenSpout, `FormulaCell::getComputedValue()`: у Carcade цена — VLOOKUP на чужую книгу.
- «···» закупки → «Загрузить контрпредложение» → `/purchases/{n}/counter?path=` (предпросмотр: станут черновиками,
  уже в предложениях, без цены, нет в закупке) → «Создать N черновиков» → `/?preset=draft&vid=table&peek=first`.
- `Purchases\Actions\MoveToOffers` — `CreateOffer` с полями ТС, `floor_price`, вендор, НДС вендора, `claim_ref` = ДЛ
  (на странице предложения у лизинговой подписан «Номер ДЛ»), лента «Создан из закупки № N, ДЛ …». Повтор того же
  файла ничего не дублирует.
- Фото переходят к предложению одной записью (`media.model_type/model_id`): путь файла у spatie — по id кадра,
  так что файлы, конверсии, порядок, скрытые кадры и водяной знак остаются на месте. Сначала сделали копированием
  (`CopyPhotosToOffer`) — владелец резонно спросил, зачем дублировать; копии на проде удалены.
- Исключение из закупки: `carsOnSite`/`showsOnSite`, выборки и числа CRM, `OffersSummary`, `Export` (строка
  удаляется из файла), `PlaceOffer`. В CRM — пункт «В предложениях» (`preset=moved`), строка с номером предложения.
  Старая ссылка менеджера на ТС закупки ведёт в предложение.
- Предложения CRM: кнопка «Оценить N» (черновики без цены продажи), окошко черновика — закупочная справа, поле
  «Цена продажи» и «В продажу» (`POST /offers/{n}/publish`): пусто — дальше; не хватает для публикации — ошибка в окошке.
- `Notify::offerPublished`: у предложения есть ТС закупки без `announced_at` → менеджерам с не отозванной ценой по ней
  `PurchaseCarOnSaleNotice` вместо общего «Нового предложения».

## Проверено локально

Настоящий файл: 62 строки основного листа, у 61 цена (4205/2024 без цены), «исключения» не читаются. На проде все
ДЛ файла есть в закупке № 1. Сквозной прогон на тестовом файле: предпросмотр, черновики с закупочной, фото,
«Оценить» (пусто — дальше, цена — в продажу и следующий), уведомление менеджеру с ценой, ТС пропала из закупки
на сайте и в CRM, старая ссылка ведёт в предложение, выгрузка без перенесённых строк.
