# Ревью денег и стоянки, чистка — 22.09.2026

Ревью диапазона `9b5adf2…845c8a2` (вендоры → операции → деньги) дало
одиннадцать находок; все закрыты одним заходом вместе с мусором, который
попался по дороге.

## Что чинилось

- **Перегон между площадками.** `Intake` больше не перезаписывает
  `accepted_at`: дата приёма — первый приём, повторный после перегона идёт
  дальше. Где ТС стояла по дням — `Vehicle::yardTimeline()` из ленты: у
  приёма, перестановки и погрузки в payload теперь `yard_id` (и `day` у
  приёма — приём бывает задним числом). `Accrual` берёт ставку по площадке того
  дня, дни в пути между площадками не считает (день погрузки и день приёма —
  считает). Старые записи ленты без `yard_id` — нынешняя площадка.
- **Счёт по день, а не по галкам.** Отрезки хранения с формы больше не
  приходят: форма шлёт `storage_until`, `IssueInvoice` под замком считает
  `Accrual` заново по этот день, чужой отрезок раньше своего (покупатель после
  вендора) отбивает с подсказкой — пропущенных дней, которые никогда не
  выставить, не бывает. PDF печётся в той же транзакции: сбой dompdf откатывает
  счёт, номер не сгорает.
- **Аннулирование.** Строки, добавленные прямо в счёте, гаснут вместе с ним;
  освобождаются только начисления, сделанные до счёта. Снять ошибочное
  начисление — сама строка «не выставлено» на ТС (`VoidCharge` наконец
  подключён, `DELETE /cars/{id}/charges/{charge}`).
- **Долги.** «Не выставлено» считается и по выданным ТС, пока хвост хранения
  не в счёте. Чтение долгов не пишет в базу: `Party::forVendor/forUser` с
  `create: false` отдают незаписанный черновик, ключ группировки — вендор.
- **Доступ.** `/money*` целиком под `park.manage`; таб «Деньги» и «Реквизиты»
  в кабинете у «только приёмки» нет; своя площадка видит счета своих ТС и
  счета без ТС (по сделкам), `MoneyController::scoped/guard`.
- `ScheduleTow` при новом сроке сбрасывает `reminded_at`/`overdue_at`;
  `Template::common` режет текст `mb_strcut`, а не байтами — ФИО перед
  телефоном находится всегда; дубль строки прайса — ошибка формы, не 500
  (`TariffController::data`).
- Найдено по дороге: `park_vehicle_events.type` был `varchar(12)`,
  `invoice_voided` в него не влезал — аннулирование падало. Расширено до 24.
  «Просрочен 3.63 дн» — `diffInDays` во float, теперь `Invoice::overdueDays()`.

## Мусор

- `park_requests.contact` одной строкой дублировал `contact_name` +
  `contact_phone` — снесён, данные разложены миграцией, форма заявки везде с
  двумя полями.
- Транслит в адресах: `?gotovye`, `?mashina`, `?stoyanka`, `?tip`, `?shablon`,
  `{zayavka}` → `done`, `car`, `yard`, `type`, `template`, `{req}`.
- Поля этапов маршрута, которые живут на стоянке и в счетах (страхователь,
  адрес, дата вывоза, исполнитель, осмотр, город/площадка, номер счёта,
  сумма, реквизиты), убраны из заготовок и миграцией из заведённых маршрутов.
- Лента «Изменена: damage_zones» → по-русски (`Support\FieldLabels`), и у
  офферов тоже.
- Общее в действиях стоянки: `Request::closeOpen()` (закрыть переданную и все
  открытые заявки типов), `Vehicle::takeSpot()` (место заглавными и проверка
  «занято»).
- `autofocus_controller.js` никто не подключал — удалён.
