# Вендоры, прайс и разбор писем — 19.09.2026

Этап 1 из трёх (Вендоры → Операции → Деньги) по плану доводки стоянки до
сервиса. Начальник просил полноценно заводить вендоров: с кем договор, сколько
берут, какая почта, куда счёт.

## Что сделано

**Один справочник.** `insurers` переименован в `vendors`, `park_clients` слит
в него (по имени, затем по доменам, иначе новая запись), `offers.insurer_id` →
`vendor_id`, `park_vehicles.client_id` → `vendor_id`. Модель `App\Vendors\Vendor`,
тип `Kind` (страховая / лизинг / банк / прочее). Экран `/settings/vendors`
с пилюлями по типу; карточка — шапка-контакт, одна шторка «Изменить» по
группам (Компания, Реквизиты, Договор с файлом, Условия, Хранение, Почта,
Документы после приёма), пилюли Обзор · Маршруты (прежний редактор) · Контакты ·
Тарифы. На стоянке `/clients` — те же вендоры, шторка правит контакт по
хранению, чек-лист документов и заметки; остальное — ссылкой в CRM.

**Контакты по ролям** (`vendor_contacts`): убытки, реализация, бухгалтерия,
хранение; «основной» и «всегда в копии». Поводы — из писем: Альфа отвечает,
что документы дают только ответственные по каждому убытку, Т-Страхование всегда
держит в копии общий адрес. Ответственный по убытку — на оффере
(`contact_name`, `contact_email`), берётся из «От:» пересланного письма.
Письмо вендору из маршрута уходит ему, cc — из контактов, ящик — вендора.

**Отправители на карточке.** `senders` — домены и адреса (tbank.ru — банк,
поэтому нужны и адреса); `Vendor::forSender` — одна дверь вместо
`Extractor::INSURERS`/`TEMPLATES` и `Client::forSender`. Шаблон разбора —
`Parser` на карточке, классы шаблонов прежние. Заведены Энергогарант, ИНСАЙТ и
Абсолют Страхование (absolutins.ru — раньше не разбирался).

**Прайс `park_tariffs`.** Не три поля на вендоре: цена зависит от площадки,
категории ТС и услуги; базовый прайс ПРАЙМ (`/settings/tariffs`) и договорной
вендора поверх него (пилюля «Тарифы»). Хранение и негабарит — ступенями по
суткам (бесплатные дни — ступень с ценой 0), эвакуация — фикс с включёнными
километрами плюс ₽/км, ещё погрузка, осмотр, простой, выдача, прочее. Даты
действия — история цен. Подбор: самый конкретный уровень целиком
(`Tariff::ladder`), ступени вендора и базовые не смешиваются. На ТС стоянки —
чип «300 ₽/сут с 4 дн». Категория ТС — `Cars\Category` (легковой / лёгкий
коммерческий / грузовой / прицеп / спецтехника / мото), `Body::category()` и
`Purchases\Kind::category()` сводятся к ней; на стоянке — поле ТС, подсказка
из письма («Тип ТС грузовики», «Газель»). Кто платит хранение — правило
вендора (`storage_payer`, `buyer_storage_after_days`, «выдавать без оплаты»),
считать по прайсу будет этап 3.

**Разбор писем — `Template::common`** на всех шаблонах и стоянке. По реальным
письмам донора: срок ответа («СРОК ТОРГОВ: до 17.08.26 до 16:00», «ответ к
01.09 до 12:00», «сообщить до 03.09.18.00»), страхователь с телефоном (только
телефон рядом со словом «клиент» — подпись сотрудника страховой не годится),
признаки `Offers\Flag` (кредитная, лизинг, в залоге, юрлицо, ограничения, ключи
не переданы; «не кредитное» — не признак), НДС, держатель («ОТП Банк»,
«Совкомбанк Лизинг», не сама страховая), требования к документам
(`DocRequirement`: акт п/п, акт хранения, соглашение, два экземпляра, цветной
скан, скан подписанного, фото ТС), «находится в …», «Марка … Модель …»
(Абсолют), категория, признак «вывоз». Код `У-001-418053/24/3` с хвостом,
кириллический код вырезается из темы по обеим азбукам. Всё это ложится на
оффер и ТС стоянки при «Завести» и показывается чипами у кандидатов
(`x-mail.candidate-facts`), в редакторе оффера — карточка «Вендор».
Вложения получают `kind` по имени (договор, акт, оценка, СТС, ПТС, соглашение,
осмотр) — чипом в документах.

**Документы вендору после приёма** — карточка на ТС: чипы из
`docs_required ?: vendor.intake_docs`, сам чип — отметка «отправлено»
(`MarkDoc`, событие в ленте). В этапе 2 станет сущностью с датами и вложениями.

Попутно: счётчики пилюль заявок считаются тем же условием, что список.

## Проверено

Локально, 375 px: список и карточка вендора, шторка с реквизитами Совкомбанка
из договора комиссии, контакт, две ступени прайса, чип ставки на ТС,
отметка документа. Разбор — на восьми реальных письмах донора (Совкомбанк ×2,
Альфа, Т-Страхование ×2, Энергогарант, Абсолют, ИНСАЙТ): вендор, код, срок,
страхователь, признаки, держатель, документы. «Завести» из кандидата — оффер
с вендором и маршрутом вывоза, ТС стоянки с контактом и чек-листом.
Локальный `scripts/imapserver.py` с Twisted 26 ломается на SEARCH — прогон
через IMAP не делался.

## На прод

`./deploy/deploy.sh` (миграция `vendors` без отката), затем
`./deploy/deploy.sh artisan db:seed --class=VendorSeeder --force` — домены,
парсеры и три новых вендора; маршруты не трогает. `insurers:refill` →
`vendors:refill`. Старые адреса `/settings/insurers*` → 301.
