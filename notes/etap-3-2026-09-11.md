# Этап 3: маршрут, сделки, часы, уведомления, live (11.09.2026)

## Что сделано

- **Страховые и маршруты** — `app/Workflow/`. `Insurer` → `Workflow` на ветку
  (`Track::Sale` двигает состояние оффера, `Track::Service` — место машины
  `CarPlace`). `Block` — то, что видит менеджер; `Stage` — наша кухня (чей
  ход `WaitsFor`, срок `DeadlineSource` + `limit_minutes`, просьба к менеджеру
  `ask_title/ask_text`, `Asks` — что приложить, `fields`, `staff_fields`);
  `Outcome` — кнопка-исход (`Actor`: мы / менеджер / время). Класс не
  `Exit`: это зарезервированное слово PHP.
- Позиция оффера — таблица `offer_positions` (строка на ветку), не
  зеркальные колонки. Просьба менеджеру — `requirements` (+ медиа `files`).
- `Workflow::problems()` — список дыр; `RevalidateWorkflow` гасит маршрут
  после любой правки, включить можно только целый. `SeedTypicalRoute` —
  кнопка «Заполнить типовым маршрутом» на пустом маршруте.
- `ChangeOfferState` остался одной дверью: после смены состояния ищет с
  текущего этапа наш исход на этап с таким состоянием (`Stage::exitInto`) и
  идёт по нему; `EnterStage` в обратную сторону зовёт `ChangeOfferState`
  с `followRoute: false`. Сделка закрывается там же: `Delivered` → done,
  всё остальное — cancelled (принятая ставка становится отклонённой).
- `offers:tick` каждую минуту (`HoldsSingleRun` через `pg_try_advisory_lock`):
  исходы по времени, `overdue_at`/`reminded_at` на позиции, закрытие
  приёма ставок. `notifications:digest` в 9:00.
- Уведомления `app/Notifications/`: база `Notice` (database + mail, если
  есть адрес и не выключено в `users.notification_settings`), подписчик
  `Notify` на события. Лента `/lk/uvedomleniya`, бейджи `Nav::badges()`.
- Live `app/Live/`: `Publisher` шлёт четыре типа — `card {number}`,
  `refresh {paths}`, `toast {message, href}`, `badges`. Клиент
  `live_controller.js` на `<body>`: по `refresh` делает Turbo-refresh
  (morph), но не пока человек печатает или открыта шторка. Тосты и бейджи
  идут от `NotificationSent` — одно место для всех уведомлений.
  Cookie подписчика ставит middleware `SubscriberCookie`, переписывая её
  только при смене набора тем.

## Проверено

Локально и на `http://200.169.180.17` в двух сеансах: публикация появляется
в каталоге без перезагрузки, закрытие приёма меняет плитку, принятая
ставка приходит менеджеру тостом и бейджем, страница сделок морфится.
Сквозной путь: черновик → публикация → ставка → принятие → согласование →
«Подтверждаю» → счёт с документом → «Оплатил» → проверка → выдача, сделка
done. Просрочка через `offers:tick` — бейдж «Срок вышел» и уведомление.

## Грабли

- Docker Hub отвечает 429 с нового адреса сервера — в `daemon.json` добавлено
  зеркало `mirror.gcr.io` (и в `server-setup.sh`).
- `migrate:fresh` не роняет sequence: в миграции `DROP SEQUENCE IF EXISTS`.
- В атрибутах Blade-компонента `@if` не работает — передавать
  `:data-turbo-confirm="$x"` (null не выводится).
- `flatMap` теряет ключи — для «id → подпись» собирать через `mapWithKeys`.
- Локально хаба нет: `MERCURE_*` пустые, `Publisher` молчит. Проверять live
  только на сервере.
