# Вход по ключу: почему не работал и что сделано (13.09.2026)

Симптом: «вход по ключу чаще всего не работает; на маке добавил — с телефона
не входит и не добавляется». На бою ключ был один (`counter=0`, ни одного
входа), в логе Postgres четыре упавшие попытки `POST /passkey/login`.

## Четыре причины

1. `config/auth.php` — провайдер `eloquent`, а пакету нужен
   `eloquent-webauthn`: ответ аутентификатора уходил в обычный
   `EloquentUserProvider` → `where "rawId" = …` → SQL-ошибка → 500. Ключи
   создавались (регистрация провайдер не трогает), вход — никогда.
2. `@laragear/webpass` 2.1.2 звал `startAuthentication(options, useAutofill)`
   позиционно, `@simplewebauthn/browser` 13 ждёт объект → conditional UI не
   включался, на телефоне при открытии `/login` всплывал модальный лист Face ID,
   после отмены кнопка оставалась скрытой.
3. iCloud Keychain синхронизирует ключ с мака на iPhone: «Добавить это
   устройство» на телефоне даёт `InvalidStateError` (ключ уже в связке) — это
   не ошибка, клиент показывал «Не удалось создать ключ».
4. `WebAuthnData::make($email, $name)` с типом `string` — у пользователя без
   почты (вход по телефону) `registerOptions` падал `TypeError`.

## Что сделано

- Провайдер `xcar-webauthn` (`App\Users\Auth\WebAuthnProvider` поверх
  пакетного): вход по ключу через проверку ассерции, пароль как раньше
  (`password_fallback`), причина отказа — `Log::warning('passkey: …')`.
- `User::webAuthnData()` — почта или телефон, имя.
- Клиент переписан на `@simplewebauthn/browser` напрямую: conditional UI на
  входе, кнопка всегда видна, подпись по устройству (Face ID / Touch ID /
  ключ), уход со страницы снимает церемонию, CSRF-токен явно. Ошибки: отмена
  — тихо; «уже добавлен» — тост без тревоги; остальное — тост и
  `POST /passkey/error` → лог (единственный след с чужого телефона).
- Morph после регистрации не прячет блок с кнопкой (`app.js`).
- Профиль: секция «Вход по ключу», строка ключа — сама кнопка удаления со
  шторкой подтверждения; чипы: хранилище по aaguid (iCloud, Google, Windows
  Hello…), «вход {дата}» из `last_used_at` (слушатель `CredentialAsserted`),
  «отключён».
- Лимит 10 ключей, throttle на все эндпоинты.
- `.env`: `WEBAUTHN_ID` — родительский домен, `WEBAUTHN_ORIGINS` не нужен
  (пакет сравнивает по host'у); пустое `WEBAUTHN_ID=` ломает регистрацию.

## Проверка

Локально на `xcar.localhost` (secure context) в панели браузера: регистрация
проходит, второй раз — «Ключ этого устройства уже добавлен», tinker
`Auth::attempt([...ответ ключа])` → `false` без SQL-ошибки. Ассерцию
(вход) панель завершить не умеет — проверять с мака и телефона на бою:
существующий ключ владельца валиден (`rp_id=xcar.ru`).
