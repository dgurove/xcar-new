# CLAUDE.md

Документация, коммиты и комментарии — **по-русски**, отвечать по-русски.

## Что это

**xcar-new** — xcar.ru заново: оптовая площадка автомобилей как
веб-приложение для телефона. Один Laravel на три хоста — три PWA одного вида:
`xcar.ru` (витрина, кабинет `/lk`, вход; **сайт закрыт** — `SiteWall`: гостю
вход и регистрация, новому — «доступ на подтверждении», отклонённому — «мы вас
не узнали» с регистрацией заново; открыты только `/kontakty` и юридические
страницы; допуск решает владелец кнопками в Telegram или в CRM →
Пользователи → «Ждут» — `DecideAccess`), `crm.xcar.ru` (всё для сотрудников:
предложения, галерея, работа — сделки (`/rabota/sdelki/{deal}` — своя страница) ·
почта · чаты, закупки, настройки — страховые, ящики, шаблоны, метки,
пользователи (только admin);
письма-кандидаты — «Из писем» рядом с «+ Новый» в предложениях и заявках;
чистые пути без `/admin`) и `park.xcar.ru` (стоянка). Поверхность — `App\Support\Surface`, по хосту её
ставит `ResolveSurface`; сотрудник на сайте видит его как менеджер, без кнопок
«править». `xcar.ru/admin/*` → 301 в CRM (`LegacyAdmin`). Главная CRM — предложения,
главная стоянки — заявки (`/zayavki` → 301 на `/`). Без Filament и
любого чужого админ-фреймворка — свой UI-кит на одних токенах.

Старый проект `../xcar.ru` — донор, не источник: оттуда берутся проверенные
решения (почта mail.ru, VIN, Carcade, приём фото, шеринг PDF, Mercure, модель
маршрута), переписываются в новую структуру. План — `~/.claude/plans/tender-jumping-quokka.md`.

## Стек и принципы

- Laravel 13, PHP 8.5, Postgres 18 (данные, очередь, сессии, кэш), FrankenPHP
  в режиме воркера (Octane), хаб Mercure внутри Caddy.
- Blade + Hotwire: Turbo (переходы, фреймы, стримы) и Stimulus (поведение).
  Контроллеры — `resources/js/controllers/<имя>_controller.js`, подключаются по
  имени файла. Никаких Alpine/Livewire/Vue.
- Каждое изменение состояния — Action + событие; контроллеры и экраны в
  модели не пишут. Событие → Mercure → Turbo Stream, никаких `poll`.
  POST всегда отвечает редиректом — иначе Turbo молча роняет ответ.
- Воркер — `resources/sw.js`, отдаётся маршрутом `/sw.js` (`PwaController::worker`)
  с версией из хэша сборки; `@vite` с `data-turbo-track=reload`.
- Код по предметным областям: `app/Offers`, `app/Mail`, `app/Park`,
  `app/Purchases`, `app/Users`, `app/Cars`, `app/Media`, `app/Live`.
  HTTP по поверхностям: `app/Http/{Site,Cabinet,Admin,Park}`; маршруты —
  `routes/{web,crm,park,auth}.php` (доменные первыми). Кабинет `/lk` — на
  всех трёх хостах, пилюли по поверхности (`Nav::cabinet`).
- Телефон — основное устройство: таб-бар, шторки `<dialog>`, камера в поле,
  16px в полях, safe-area. Системные `<input type=date>`, `<select>`.
- Вид — язык витрины xcar.ru, один на витрину, кабинет, админку и стоянку:
  шапка с квадратами (телефон) и рядами капсул (десктоп; квадрат обрезает
  соседям обращённую к нему сторону), логотип — знак с иконки приложения
  (`x-ui.brand`: xcar · CRM · P, `public/images/{crm,park}*.svg` из
  `resources/icons`), в CRM и на стоянке нет поиска на телефоне, нижний таб-бар
  с аватаром в «Кабинете», подвал и крошки только на сайте (CRM и стоянка —
  `noindex`), `h1` + ряд действий, тулбар списка
  (`x-ui.toolbar`: сортировка, пилюли, вид, фильтры в шторке; `sort-side="right"` уносит сортировку к фильтрам, чтобы слева были одни пилюли-режимы), одна
  карточка на строку и плитку (`x-offer.card` в `.cards`), страница объекта
  с правой колонкой и полосой действий (`x-ui.action-bar`), кабинет с
  пилюлями разделов (`x-ui.cabinet`), вход на фото паркинга. Классы кита и
  девять правил — в шапке `resources/css/app.css`; витрина кита — `/ui` на
  CRM (local). Тёмная тема — `.dark` в CSS, утилиты `dark:` не пишем.
- Ощущение приложения (см. блоки «нажатие», «ленты», «хром под пальцем» в
  `app.css` и `resources/js/{app,sheet,confirm,net}.js`): у всего нажимаемого
  есть `:active`, голый `:hover` пишется только внутри `@media (hover: hover)`;
  токены движения `--ease-out/--ease-in/--ease-spring`, `--dur-fast/--dur/--dur-slow`;
  переходы push/pop, а `replace`-визит (табы, сортировка, пилюли, фильтры,
  поиск — `data-turbo-action="replace"`) и morph-refresh без анимации; страница
  объекта отдаёт `x-ui.shell back="['Раздел', '/url']"` — «‹ Раздел» в шапке;
  подтверждения — `data-turbo-confirm` через свою шторку (`confirm.js`), не
  `window.confirm`; шторки открываются/закрываются через `sheet.js` (свайп
  вниз, уход); 419/429/обрыв сети — `net.js` (тост, повтор), страницы ошибок —
  `resources/views/errors/*` на оболочке; серверный flash — `<template id="flash">`,
  узел `#toasts` постоянный; `x-ui.field` сам ставит клавиатуру по имени поля;
  черновики форм — `data-controller="draft"` (localStorage, восстановление в
  нетронутые поля); живой канал — `resources/js/live.js` (один на сеанс);
  открытая шторка — запись в истории (`sheet.js`); таймеры — общий такт и
  `timer:done`, `CloseBids` закрывает приём точно в срок; список помнит вид и
  сортировку (`ListPrefs`); лента на телефоне дотягивается сама (`[data-pages]`);
  строки писем и уведомлений смахиваются (`x-ui.swipe`); фото ужимаются в
  телефоне до отправки, `sha` исходника приходит полем (`PhotoIngest::fromPhone`);
  воркер отдаёт последний экран из кэша, страница старше 15 с перечитывает себя;
  хром — системным шрифтом (`--font-ui`), установленное приложение (cookie `app`,
  `MarkInstalled`) без первого экрана и подвала; тактильный отклик — `switch` под
  пальцем; долгое нажатие по карточке — меню (`longpress.js`).
  Подробно — `notes/prilozhenie-2026-09-13.md`.
- CRM и стоянка плотнее витрины: `<body class="surface-crm|park">` включает
  поля 44/40 px с подписью 13 px, карточки с меньшими полями, плитки списка с
  фото на треть высоты и строки в 80 px (блок «Плотность» в `app.css`).
  Формы объектов — `grid grid-cols-2 gap-3 lg:grid-cols-3`, широкие поля через
  проп `span` у `x-ui.field`; страница объекта: слева форма, справа колонка
  22rem, внизу во всю ширину `x-ui.photos` (ряд фото: плитка «добавить»
  стоит вне ленты — в ленте snap, и всё без привязки уезжает за край;
  файлы можно бросить на карточку; глаз · поворот · корзина,
  скрытый кадр серый, главное — первое, порядок перетаскиванием, клик —
  Viewer.js с теми же кнопками; в полосе кадры `w320`, поворот —
  `RotatePhoto` на месте вместе с конверсиями) и
  документы через `x-ui.file` (квадрат с расширением). Без фото — `x-ui.car-blank`.
  Плитки-числа — `x-ui.stat`. VIN — поле `x-ui.vin` с квадратом ✨ (загорается
  на семнадцатом знаке, по клику или Enter `vin_controller` заполняет пустые
  поля формы, заполненные вспыхивают; тост — только о том, чего в полях не
  видно). Декодер `App\Cars\Vin` (таблицы в `resources/vin`) плюс **память
  базы** `VinMemory`/`vin_facts`: каждая сохранённая машина с VIN и маркой
  запоминается (`RememberVin` из Actions офферов, закупок, стоянки), при
  разборе берутся записи с самым длинным общим началом VIN и подставляются
  поля, в которых они согласны; память важнее таблиц. `vin:learn` — один раз
  запомнить всё. Год из VIN не подставляется, когда марка его не кодирует
  (Renault, Mercedes, BMW). Цифры табличные (`.nums`) только у
  цен, счётчиков и таймеров — даты и номера обычными.
- Тесты во время разработки не пишем — только когда без теста ошибка молчалива
  и дорога. Проверка — глазами, с телефона.
- Подписей-пояснений под элементами нет: непонятный блок переделывается.
- Факты не склеиваются в строку через « · » — это признак ленивой вёрстки.
  Факты — чипами `.tag`/`.chip` рядом (как `x-offer.tags`), человек —
  `x-ui.person` (аватар и имя), номер — отдельным `nums`-чипом; в тексте
  уведомлений и Telegram — обычная фраза. На десктопе широкой строке
  положена вторая колонка, а не всё вниз. Одно действие у элемента —
  элемент и есть кнопка с подтверждением (`data-turbo-confirm`,
  `data-turbo-confirm-text` — абзац с деталями, `-quote`/`-quote-by` — цитата с подписью), не кнопка рядом;
  вторичные данные не крупнее основного текста.
- Словарь: слова «ставка» нет нигде. Менеджер **подтверждает** предложение
  своей ценой — у него «подтверждения»; посетитель **проявляет интерес**;
  «предложение» — только машина. В текстах «автомобиль», не «машина»;
  «страхователь» — только в наших этапах вывоза.

## Команды

```bash
./serve-local.sh                 # http://xcar.localhost:8010 (php@8.5 и postgres из brew)
php artisan queue:work database-long --queue=long,mail --stop-when-empty   # почта, фото, закупки
php artisan queue:work --stop-when-empty                                   # конверсии, уведомления
php artisan offers:tick | mail:sync | mail:reconcile | notifications:digest | push:keys
npm run build                    # ассеты; npm run dev — с горячей перезагрузкой
node scripts/icons.mjs           # иконки трёх приложений и экраны запуска iOS из resources/icons
./deploy/server-setup.sh         # один раз на новый сервер
./deploy/deploy.sh               # выкладка: снимок git → сборка → бэкап базы → миграции → up → таймеры
./deploy/deploy.sh backup|check|artisan …|rollback TAG
```

Вход глазами без пароля — `/dev/vhod/{id}` (только local).
Локальная база `xcar_new` (роль xcar/xcar, порт 5432). Порт 8010, потому
что 8000 занят старым проектом. Хосты локально как в бою — три имени под
одним родителем: `http://xcar.localhost:8010`, `http://crm.xcar.localhost:8010`,
`http://park.xcar.localhost:8010`; cookie сессии на `.xcar.localhost` (в бою
`.xcar.ru`) — один вход и один выход на всех трёх. Почта локально — IMAP-сервер на Twisted
`scripts/imapserver.py (venv с twisted)` (порт 1143, `offer`/`deal` : `parol`, письма
файлами в `imapdrop/<user>/`) и `mailpit` (SMTP 1025, веб 8025); хаба Mercure
локально нет — live проверяется на сервере.

## Диски

Три диска Laravel: `media` (публичное, Caddy отдаёт `/media/*` сам),
`private` (письма-blobs, документы, чаты, файлы просьб — только через
контроллеры), `cache` (воспроизводимое: PDF шеринга, части писем из ящика,
outbox, tmp — не бэкапится, `storage:gc` чистит по срокам). Правило: что
можно пересчитать — в `cache`, что нельзя — в `private` или `media`.
