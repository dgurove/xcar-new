# CLAUDE.md

Документация, коммиты, комментарии и ответы — **по-русски**.

## Что это

**xcar-new** — xcar.ru заново: оптовая площадка автомобилей как веб-приложение
для телефона. Один Laravel на три хоста — три PWA одного вида: `xcar.ru`
(витрина, кабинет `/account`, вход), `crm.xcar.ru` (сотрудники: предложения,
галерея, работа — сделки · почта · чаты, закупки, настройки; пути без
`/admin`, старые `xcar.ru/admin/*` → 301), `park.xcar.ru` (стоянка).
Поверхность — `App\Support\Surface`, ставит `ResolveSurface` по хосту; чужие
маршруты на хосте — 404, вошедший не-сотрудник на CRM и стоянке — стена
`auth.foreign` (403, без шапки: в кабинет на сайт, написать, выйти). **Адреса только английские** (`/account/deals`,
`/work/mail`); транслита нет, слова «ставки» нет нигде. Старые адреса транслитом —
301 через `Support\Paths` + `RedirectLegacyPaths` (единственное место со старыми именами). **Сайт закрыт, саморегистрации нет**: новый человек
приходит только по пригласительной ссылке `/i/{code}`; прежний допуск по
заявке (`SiteWall`, `DecideAccess`, Telegram `Registration`) в коде остался,
но не используется. Без Filament и чужих админ-фреймворков — свой UI-кит.

Старый проект `../xcar.ru` — донор, не источник. Подробности по модулям и
решения владельца — `notes/*.md` (главное — `notes/moduli-podrobno-2026-09-16.md`).

## Стек и принципы

- Laravel 13, PHP 8.5, Postgres 18 (данные, очередь, сессии, кэш),
  FrankenPHP/Octane, Mercure внутри Caddy. Blade + Turbo + Stimulus
  (`resources/js/controllers/<имя>_controller.js`), никаких Alpine/Livewire/Vue.
- Изменение состояния — Action + событие; контроллеры и экраны в модели не
  пишут. Событие → Mercure → Turbo Stream, никаких `poll`. POST всегда
  отвечает редиректом. Код по областям `app/{Offers,Mail,Park,Purchases,Users,
  Cars,Media,Live,Chats,Telegram,Workflow,Notifications,Push,Storage}`, HTTP по
  поверхностям `app/Http/{Site,Cabinet,Admin,Park,Auth}`, маршруты
  `routes/{web,crm,park,auth}.php`.
- Телефон — основное устройство: таб-бар без иконок — у раздела капсула с числом позиций (`Nav::totals`,
  кэш полминуты, серая; у текущего лаймовая одной ширины под три цифры), сверху лаймовый бейдж нового
  (`Nav::badges`), у кабинета аватар, без позиций — точка (`.tab-mark`); шторки `<dialog>` (`sheet.js`),
  safe-area, 16px в полях, системные `<select>`/`<input type=date>`.
  Проверка — глазами, с телефона (Browser pane 375 px), тесты во время
  разработки не пишем — только когда ошибка молчалива и дорога.
- Один язык вида на витрину, кабинет, CRM и стоянку: классы кита и десять
  правил — в шапке `resources/css/app.css` (лайм — глагол; тёмное — только
  хром; теней и обводок нет; скругления 24/16/12/8; заголовки 500; подписей
  под элементами нет; числа табличные, полужирным только цена и главный
  показатель; пустой блок не рисуется; фраза в интерфейсе — без точки в конце). Шапка,

  `notes/prilozhenie-2026-09-13.md`.
- **Три вида списка** (`?vid=grid|list|table`, `Support\ListView`, память

  `ListView::pick`; страницы — `x-ui.pager` вместо `links()`, на телефоне те же (бесконечной ленты нет):

  сетка областей (закладка в правом верхнем углу, в плитке на кадре; под ней цена, внизу кнопка, город

  ref стоянки; заголовок «Марка, модель», слова «Машина» в шапках нет): плитки и строки — одна разметка `x-offer.card` в `.cards`;
  таблица — `x-ui.table` (плотные строки, чётные заливкой, шапка липкая,
  обводок нет) со строками `x-{offer,purchase,park}.table-row`; в CRM
  предложения, галерея, машины закупки (`crm-purchase-cars`), на стоянке —
  машины; на сайте — каталог и галерея (`x-offer.site-table-row`),
  избранное, машины закупки (`x-purchase.site-table-row`, `purchase-cars`). Переключатель `x-ui.view-switch`
  — круглая кнопка с иконкой текущего вида, меню `x-ui`-`.menu` (`menu_controller`, popover).
  **Окошко строки** (`peek_controller`, только в таблице): нажатие по строке —
  выделение и окошко с фреймом `peek` (`x-ui.peek`: лента фото `x-offer.gallery strip`
  с Viewer во весь экран, название, метки, цена справа `aside`, факты, ряд `actions`,
  тело — формы, характеристики, описание; свежая строка едет в ответе слотом `row`).
  Высота везде фиксированная (телефон — полэкрана поверх таб-бара или во весь экран
  за ручку, положение помнится в localStorage; от 1024 — панель справа от таблицы,
  липкая, во всю высоту), лишнее прокручивается внутри; стрелки у счётчика — по строкам.
  Характеристики — метками и фактами, отдельного списка нет.

  (обычный `back()`, flash, ошибки) на адрес окошка — контроллеры про окошко не знают;
  `session('peek-advance')` просит перейти к следующей строке `data-unpriced`.
  Открытое окошко — запись в истории (как шторка): «Назад» закрывает его, ссылка из
  него сначала снимает запись; `?peek=ref|first` открывает строку сразу.
  Enter — раскрыть/свернуть, ⌘Enter или двойное нажатие — на страницу, ↑/↓ — по строкам.
  Содержимое по месту: закупка CRM — оценка и выбор предложений; предложения CRM —
  +15 мин / +1 ч, состояние (`.menu`), подтверждения принять/отклонить, интерес;
  стоянка — принять, переставить, выдать, акты, заметка; сайт — подтвердить ценой
  (быстрые кнопки, комментарий, отозвать), проявить интерес / узнать цену, избранное,
  закупка — предложить / изменить / отозвать цену. Переключение строк без скачка:
  прошлое содержимое притушено (`aria-busy`), пока едет новое.
  Эндпоинты `/offers/{n}/peek` (`?gallery=1` — строка галереи), `/purchases/{n}/{car}/peek`
  на обоих хостах, `/cars/{id}/peek` на стоянке. «Сколько
  прошло» в таблицах — `Support\Ago::short` («3 ч», «2 дн»).
- **Экран — как в приложении:** одно главное действие экрана — в
  `x-ui.action-bar`, не иконкой в тулбаре; человек и группа — шапка-контакт
  `x-ui.contact` (кружок, имя-`h1`, чипы, ряд круглых действий `.acts` с
  подписью); списки людей — `.row` (аватар 44, имя, `.row-sub` чипами ≤3);
  машины внутри кабинета — строками (`cabinet/buyers/offer-row`), полная
  карточка только в ленте; выбор людей — `.row-check` с галкой справа, машин —
  `.pick-card`; пустое состояние — одна фраза; на десктопе широкой строке —
  вторая колонка, а не всё вниз.
- Факты не склеиваются через « · » — чипами `.tag`/`.chip`, человек —
  `x-ui.person`, номер — `nums`-чипом. Место (город, адрес, стоянка, «где сейчас») —
  всегда `x-ui.place` с меткой на карте перед текстом (форма — классом снаружи: tag,
  chip, mark, текст); VIN на экране — всегда `x-ui.vin-code`: нажатие копирует
  (иконка справа, тост «VIN в буфере»), скрытый — звёздочки без копирования. Одно действие у элемента — элемент и
  есть кнопка с подтверждением, не кнопка рядом. Подписей-пояснений нет:
  непонятный блок переделывается. Вторичное не крупнее основного.
- **Цена не разрывается:** разряды и ₽ — неразрывными пробелами через
  `Support\Money::nums/rub` (голого `number_format(…, ' ')` в Blade нет);
  «от → до» переносится только целыми частями, `fit_controller` ужимает шрифт
  лишь когда не влезает неразрывный кусок. `.nums` — только у цен, счётчиков и
  таймеров.
- Словарь: слова «ставка» нет; менеджер **подтверждает** предложение ценой
  («подтверждения»); покупатель **проявляет интерес**; менеджер **открывает**
  предложения покупателям («показ»); «предложение» — только ТС;
  слова «машина» в интерфейсе нет: коротко — «ТС» (таб, чипы, выбор, тосты),
  заголовок карточки — «Транспортное средство», столбец названия —
  «Марка, модель»; в текстах витрины — «автомобиль». Слова «битые» нет никогда.
- VIN — `App\Cars\Vin` + память базы `VinMemory` (память важнее таблиц; год из
  VIN не подставляется, если марка его не кодирует).

## Роли, цены, покупатели

Роли `Users\Role`: `admin`/`moderator` — сотрудники (CRM); `manager` —
внешний партнёр: подтверждает ценой, ведёт сделки, закупки и **своих
покупателей** в кабинете на сайте; `buyer` — покупатель менеджера: видит
только открытое ему, одну цену и «Проявить интерес», пишет своему менеджеру чатом по предложению; `visitor` — мёртвая.
Способности — методы `Role` явными списками (`canBid`, `canSeePurchases`,
`canSeeGallery`, `canChat`, `canShare`, `canInterest`).

**Три цены оффера:** `floor_price` закупочная (только сотрудник),
`publish_price` заявленная (пусто — равна закупочной; менеджер считает её
закупочной, `Offer::declaredPrice()`, от неё `minBid()`), `asking_price`
продажи. Кто что видит — одна дверь `Offers\PriceView::for($offer, $user)`.

**Кто что видит — одна дверь** `Offer::scopeVisibleTo(?User)` / `isVisibleTo()`:
сотрудник всё; менеджер — Open/Gallery своего круга (`managers_limited` +
`offer_managers`, по умолчанию все); покупатель — Open с показом его
менеджера (лично или через группу); гость — ничего. Через неё идут каталог,
страница, live-фрагменты, PDF, подтверждение, интерес, избранное, счётчики.

**Покупатели.** `login` (латиница; вход одним полем логин / телефон / почта),
`manager_id`, `contact_fields` (что покупатель вправе указывать — снимок с
приглашения). Приглашение `Users\Invite` (`/i/{code}`): менеджер зовёт
покупателей (многоразовая, `fields`, группа), админ — менеджера, модератора или
админа (`max_uses` 1, `expires_at`, без названия, `ManagerJoined`) или покупателя
от имени менеджера. Руками в CRM людей не заводят — только ссылкой. Закрыть доступ
уже допущенному — `DecideAccess::reject` (сессии и пуши гасятся, его ссылки выключаются,
покупатели менеджера закрываются вместе с ним), вернуть — «Отклонённые → Открыть»;
удалить (`UserController::destroy`) — только без следов (`traces`: подтверждения, сделки,
предложения, покупатели, чаты). Одна дверь `IssueInvite`, один экран `x-invites.list`
(`/account/invites` и CRM «Пользователи → Ссылки»; сам экран «Пользователи» — один на CRM `/settings/users` и сайте `/account/users`, `UserController::base()`), доступ
`Invite::manageableBy` — менеджер видит и сделанные для него админом. Новая
ссылка — первая строка списка. В кабинете `h1` нет: раздел называет пилюля.
В CRM кабинет = «Настройки» `/settings`: профиль — корень и первая пилюля, дальше Пользователи · Вендоры · Тарифы · Ящики · Шаблоны · Метки · Уведомления, все экраны настроек в `x-ui.cabinet`; `/account` на CRM → 301 `/settings`.
Пилюль у менеджера шесть: Профиль · Покупатели · Сделки · Чаты · Избранное ·
Уведомления; интерес (`/account/interest`) и приглашения — строки над списком
«Покупателей» (`Nav::link(also:)` держит пилюлю активной и даёт «назад»),
подтверждения — секции «Ждут решения» и «Не состоялись» на экране «Сделки».
`AcceptInvite` даёт `approved_at` сразу.
Группы `BuyerGroup`; показы `Offers\Showing` (ровно одно из user/group),
`ShowOffers`/`HideOffers`, покупателю одно уведомление на пачку, live —
`refresh` в `user/{id}` (тему `catalog` покупатель не слушает). Интерес
покупателя — `BuyerInterestNotice` его менеджеру. Настройки уведомлений — `Notifications\Categories` (что можно выключить по роли), `Notice::category/critical`, `User::wants/quietHours`, экран `/account/notifications/settings`, отписка из письма подписанной ссылкой. Ссылка на новый пароль —
`IssuePasswordLink` (`/password/link/{token}`, сутки, одноразовая) — менеджер
покупателю, админ кому угодно. Админ передаёт покупателя `TransferBuyer`.
Форма в шторке после успешного POST закрывается сама (`app.js`).

## Ключевые двери и договорённости

- Состояния оффера — только `Workflow\ChangeOfferState`. **Приём
  подтверждений — срок, не состояние**: `Offer::bidsOpen()`/`closed()` по
  `bids_close_at`, продление «+15 мин / +1 ч»; у закупок так же.
- Шеринг PDF — `Offers\Share` (`Subject`, `SharePdf`, `Caption`), тумблер
  `share_locked` серит «Поделиться», PDF — 422, кадры под водяным знаком
  (`Media\Watermark`, `StampPhoto`/`UnstampPhoto`, `media:restamp` после
  перерисовки знака). Share отдаёт только файл — файл и текст вместе теряют файл.
- «Рекомендуем» — `offers.recommended`, чекбокс в редакторе; у названия синий кружок с галочкой
  `x-offer.recommended` (с `label` — тег с подписью: страница, окошко); фильтр — первая сужающая
  пилюля `view=recommended` (`CatalogQuery::VIEWS`) и пресет `recommended` в CRM; пилюля есть, пока
  отмеченные есть. Одно слово везде. Тулбар каталога один на все роли: что кому показывать, решают
  `CatalogQuery::allowedSorts/allowedViews`, не ветки в blade.
- Чаты — мессенджер по образцу Авито: чат — пара (оффер, участник) + вторая сторона:
  `manager_id` пуст — сотрудники площадки (CRM «Чаты»), задан — менеджер покупателя; сотрудник
  такие переписки только читает (пресет «Покупатели с менеджерами», `x-chat.box readonly`, счётчики
  не трогает). Одна дверь `Chat::isCounterpart($user)` для счётчиков, «моих» сообщений, live-тем и
  уведомлений; читать — `allows()`, писать — `canPost()`; `User::canChat()` — покупателю только с
  менеджером. Экран `/account/chats` у всех (сотруднику — и чаты площадки: другой хост в установленном
  приложении открывается во встроенном браузере, поэтому адреса уведомлений и пушей — без хоста, на CRM
  `/account/chats/{id}` → `/work/chats/{id}`) и `/work/chats` в CRM — один рисунок: панель строк
  `x-chat.row` (фото ТС с аватаром собеседника в углу, последнее, бейдж; «Администрация XCar» — `Chat::PLATFORM` — в списке всегда: обращение ещё не заведено — строка ведёт на `/account/chats/support`, первое сообщение уходит на `POST /chats/support`). Сообщение площадке без живого ответа сотрудника → `Chats\Jobs\SendAutoReply` (через 2 с «печатает», через 5 — пузырь `Actions\AutoReply`: Staff без автора, текст по времени суток, ссылка `[в настройках](/…)` — `Linkify`); один раз до ответа сотрудника, чат — `x-chat.screen`; аватар и имя в его баре ведут к человеку: менеджеру — `/account/buyers/{id}?chat=` («‹ Чат»), сотруднику — карточка `/settings/users/{id}?chat=` (`Admin\UserController::show`, любому сотруднику: контакт, чаты, сделки, интерес, админу шит `x-admin.user-sheet`), покупателю и пишущим площадке — шторка `x-chat.contact`; статус менеджера и площадки покупателю — не `seen_at`, а `Chats\Hours::presence` (9–21 МСК «в сети», иначе «был в сети N ч N мин назад» от 21:00)
  (бар собеседника с «в сети» по `users.seen_at`/`TouchSeen`, полоска ТС, лента, бар поля); на
  телефоне экран чата — экран приложения: шапка, таб-бар, подвал и пилюли скрыты через
  `body:has(.chat-page)`, свой «‹» в баре; от 1024 — панель «список | фрейм `chat-screen`»
  (`split_controller`). «Написать» со страницы ТС — `/account/chats/offer/{n}` (чат есть →
  редирект, нет — экран с пустой лентой, первое сообщение заводит чат и подменяет адрес); на

  только без следов (заявки, бумаги, деньги — тоже следы). Главная стоянки —
  «Сегодня» (`Park\Today::build` — одна функция экрану и дайджесту): секции
  Просрочено · Связаться · Забрать · Принять · Выдать · Осмотреть, переставить ·
  Отправить вендору (`park_docs_days`) · Стоят долго (`Park\Idle::warn/danger`
  из `park_idle_days`), у секции ссылка «все»; `/requests` — весь список: три вида
  (`x-park.request-card`, `x-park.request-row`, окошко `/requests/{id}/peek`),
  пресеты типов и «Готовые», поиск по ТС, вендор, площадка, «Мои». Доступ: своя
  площадка `users.park_yard_id` (`Park\Scope`), «только приёмка»
  `park_readonly` (`User::canManagePark`, middleware `park.manage`).
  **Процесс страховой** (с 25.09.2026): «Завести» из письма открывает **форму заявки** `/requests/new?candidate=`
  с полями из письма и **письмами рядом** (`x-mail.aside` — от 1024 вторая колонка, на телефоне шторка
  через `x-mail.aside-button`; тела писем — `x-mail.message`, тот же компонент на странице ветки);
  `Park\Actions\PromoteCandidate::attach` помечает кандидата и привязывает ветки. Новая заявка на приём
  сначала ждёт звонка (`Request::needsCall`, секция «Связаться» и пресет `call`): `Contact` — эвакуатор
  (заявка становится `tow` и назначается той же шторкой), привезёт сам (`delivery=self`, срок), не
  дозвонились (`next_call_at`, напоминание `RequestCall` в `park:tick`); «Беру» — `/requests/{id}/take`.

  `RefuseRelease`: осмотр с `refused`, ТС остаётся, акт с отказом и редактор письма.

  маршрута вывоза (`Workflow::stageForPlace`); запуск маршрута вывоза (кнопкой

  категория `park` (`ParkNotice`: письмо, назначение, срок, простой), Telegram
  `ParkLetter`, `ParkSold` и `ParkDigest` (`park:digest` 9:00 по будням), `park:tick` каждые

- **Деньги** (`app/Billing`, с 21.09.2026). Контрагент — `billing_parties`
  (юрлицо с реквизитами или физлицо с паспортом; одна строка `is_self` — ПРАЙМ;
  `Party::forVendor/forUser` заводят по первому счёту, чтение — `create: false`,
  базу не трогает). Хранение считается **на лету** (`Accrual::storage`): сутки —
  календарный день, день приёма — первые, день выдачи тоже считается; `accepted_at`
  — первый приём, перегон между площадками его не сдвигает, дни в пути не
  считаются, ставка — по площадке того дня (`Vehicle::yardTimeline` из ленты:
  `yard_id` и `day` в payload приёма/перестановки/погрузки); ставка на каждый
  день из лестницы прайса (прайс, заведённый позже, действует на прошлые
  невыставленные дни), персональная `storage_rate` поверх, негабарит
  прибавляется, плательщик режет период (`storage_payer`,
  `buyer_storage_after_days` — дни за счёт вендора после продажи (`sold_at` или сделка CRM) → дальше
  покупатель (`Party::forPickup` из письма или покупатель сделки, `buyer_party_id`) по ставке вендора ×
  `buyer_rate_multiplier`, `Accrual::buyerFrom/buyerRate`). При выдаче «Принял наличными» —
  `SettleStorage`: счета по плательщикам по день выдачи, покупателю тут же оплата наличными. В счёт хранение
  идёт **по день** (`storage_until`): `IssueInvoice` считает отрезки заново под
  замком, чужой отрезок раньше своего отбивает, пропусков не бывает;
  `storage_billed_until` на ТС. Строки, добавленные в счёте, гаснут вместе с ним
  при аннулировании, начисленное до счёта — освобождается (`VoidCharge` — снять
  начисление, пока оно не в счёте: сама строка на ТС). PDF — в той же
  транзакции: счёта без файла не бывает. Счёт `billing_invoices` в обе стороны: `issued` — нам должны (номер
  сквозной в году, PDF-снимок dompdf в `file`), `owed` — мы должны (перечисление
  вендору назначенной цены по договору комиссии в `payment_days` рабочих дней —
  `IssueTransferObligation` с приёма, а также при правке договора после приёма —
  пересчёт неоплаченного, аннулирование при снятии договора); `Party::self()`
  создаёт ПРАЙМ из конфига, если строки нет; состояния `issued|paid|void`, просрочка и
  «частично» вычисляются, `light()` — светофор. Оплаты частями
  (`RecordPayment`, не больше остатка, платёжка сканом — media `slip` у
  `Payment`), у выставленного счёта правятся срок, чужой номер и заметка;
  аннулирование только без оплат (откатывает `storage_billed_until`). `Ledger` — долги по контрагенту, по ТС,
  по всем, месяц. Выдача с долгом — только с `force` или у вендора «выдавать без
  оплаты», и это в ленте. Экраны стоянки: `/money` (пресеты, окошко, PDF, акт
  хранения), карточка счёта, `/money/debts`, `/money/summary`, `/money/parties`;
  из ТС — `/cars/{id}/invoices/new` (хранение по день, начисления, свободные
  строки) и шторка «Начислить»; раздел `/money` — только `park.manage`, своя
  площадка видит счета своих ТС; карточка «Договор» на ТС
  (комиссия / хранение, номер, назначенная цена, ПТС, СТС, комитент). Документы
  страницей на печать: акт хранения по счёту, договор комиссии и акт
  приёма-передачи по образцу Совкомбанка (`/acts/{id}/contract|handover`,
  сумма прописью `Support\Words`). `billing:tick` 9:05 — просрочка раз, владельцу
  в Telegram с кнопкой «Оплачен» раз в неделю. У вендора в CRM — пилюля «Деньги».
  **Закрытие месяца** (`Billing\Closing`, `/money/closing?month=`): периодичность у вендора и ТС
  (`Cadence` `monthly|release`, `Vehicle::cadence()`) — помесячные по конец месяца (текущий — по сегодня),
  «после выдачи» — за весь период, покупатель отдельной строкой; экран с галочками, «Выставить выбранные»
  — `IssueInvoice` + акт PDF (`StorageActPdf`, media `act`); `billing:close-month` 1-го в 06:00 только
  считает и зовёт (Telegram `ClosingReady`, `ParkNotice::closing`). «Отправить» на счёте —
  `/mail/new?invoice=` с PDF счёта и акта бухгалтерии вендора, `sent_at`. Ничего не отправляется само.

## Команды

```bash
./serve-local.sh                 # http://xcar.localhost:8010 (php@8.5 и postgres из brew)
php artisan queue:work database-long --queue=long,mail --stop-when-empty   # почта, фото, закупки
php artisan queue:work --stop-when-empty                                   # конверсии, уведомления
php artisan offers:tick | park:tick | park:digest | billing:tick | mail:sync | mail:reconcile | push:keys | media:restamp | vendors:refill
npm run build                    # ассеты; npm run dev — с горячей перезагрузкой
node scripts/icons.mjs           # иконки, экраны запуска, водяной знак из resources/icons
./deploy/deploy.sh               # выкладка: снимок git → сборка → бэкап базы → миграции → up
./deploy/deploy.sh backup|check|artisan …|rollback TAG
```

Вход глазами без пароля — `/dev/login/{id}` (только local). Хосты локально как
в бою: `xcar.localhost`, `crm.xcar.localhost`, `park.xcar.localhost` :8010,
cookie на `.xcar.localhost`. База `xcar_new` (xcar/xcar). Почта локально —
`scripts/imapserver.py` (1143) и mailpit (1025/8025); Mercure локально нет.

## Диски

`media` (публичное, Caddy отдаёт `/media/*`), `private` (письма, документы,
